# 13 — Critical path: what must ACTUALLY work (v1.3, authoritative)

**This document is a build contract, not a claim of artistic success.** Keep the complete v1.2 package and the unchanged `05_APPROVED_13_PART_REFERENCE.txt`. v1.3 adds implementation authority and build-before-learning sequencing. Where a v1.2 document says to immediately execute paid learning or render in the first coding session, this v1.3 package instead requires **an offline engineering-build audit ZIP first**. Nothing about source isolation, multi-gap clustered learning, frame-by-frame study, artwork-first approval, user feedback, or visual transfer was removed.

## A. The exact critical chain

`Fresh originals → source frames actually seen → picture-level causal candidate → conditional style decision → manufacturing recipe → versioned skill-owned prompt+reference+edit program → real image-provider call → original full-size art → coherent character/asset family → user approval → motion/camera/choreography code → actual frames/video → comparison and repair → frozen-method unfamiliar transfer`.

A broken link invalidates claims downstream, however many tests pass. **Technical enforcement prevents bypass; it does not create artistic expertise.** Creation methods, reference conditioning, and revisions to art production itself make outputs better.

## C. Critical corrections to v1.2

1. **No individual one-problem bottleneck**: the Gap Finder keeps all visible important gaps, picks a *connected high-leverage cluster*, and preserves isolated defects without conflating causes. Within a cluster, investigate in dependency order; when useful, use independent workers for source extraction or unbiased review, not uncoordinated artistic decisions.
2. **No 'style adjective' shortcut**: the observation compiler can only use concrete picture-level evidence with conditional decisions, exact execution operators and authorized reference images. It does not proclaim a rule because a design element repeats.
3. **No checking as a substitute for creation**: correction modifies art planning, generator conditioning, model/edit route, or the skill's executable operations. Tests only prove the correction path is wired.
4. **No 'make a better prompt' free-form branch**: when required style fields are missing, return a targeted research ticket; don't let the producer's LLM hallucinate clauses.
5. **No assumed motion-ready PNG**: ordinary PNG is a flattened raster unless its alpha, masks, layers or separate states are actually created; document what was produced.
6. **No unverifiable cloud setup**: the Runware API key is a credential, not a fixed model. Confirm actual model capability and exact identifier before setting defaults.
7. **No hidden work after first coding session**: BUILD OFFLINE → ZIP → independent audit → fix failures → authorize paid source and art learning. Do not claim the first build is complete just because docs exist.

## D. Real limitation that no spec can erase

Source footage does not reveal the studio's unique internal methods, and prompt-conditioned image generation does not guarantee a desired silhouette, face, or exact pixel-level consistency. The system can rigorously prevent **unapproved extra style instructions**, choose better producing operations, and force failures to be diagnosed at the correct stage. Professional artistic quality remains an empirical result, not a consequence of checking every field.
