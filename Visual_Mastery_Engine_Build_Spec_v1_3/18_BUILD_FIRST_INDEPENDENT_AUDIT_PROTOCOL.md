## Phase 2 — independent audit questions (ask THESE, not 'is everything working?')

A. Can any production codepath submit an aesthetic `positivePrompt` that did not come from pinned skill-owned clauses? Trace actual gateway callers.

B. In an offline fixture, does changing one selected style decision change the exact compiled provider payload (or chosen edit/reference operation)? Does changing only a nonselected report paragraph leave production unchanged?

C. Can a source-specific observation ('the source insect has six legs in one shot') be promoted to a universal style rule? Do the data contracts retain exception and condition requirements?

D. Can the observation engine produce a `QuestionTrace` and actionable producing recipe from a connected cluster, or only save descriptive text? Show actual code and fixture.

E. Does the observation-to-skill contract require a real operator, typed inputs/outputs, selected references and connected rules for every important claimed decision? Can the code run a synthetic one end-to-end?

F. Can a missing necessary style decision be silently filled with general-model prose or generic provider defaults? Demonstrate blocked paths.

G. Are frame indices/PTS authentic, and are full-frame indexed coverage, verified model-seen coverage and native artistic understanding distinguished? Probe source decode actual bytes.

H. Kill at request-in-flight, result-received and semantic-committed states: do retries reconcile provider UUIDs/outputs and preserve current artistic question and boundary states?

I. Are skill-owned reference/identity images actually included in compiled jobs, respecting provider limits? Does the code send them or merely log reference IDs?

J. Is the Runware model ID actually verified rather than guessed from '7B'? Is paid generation disabled without explicit user consent and a spend cap? Are source-frame uploads separately controlled?

K. For generated raster output, does code decode actual bytes, get correct dimension/alpha/mask and preserve original pixel coordinate mapping? Does `PNG` with opaque alpha get treated as opaque?

L. Can a complete original character pose and contact plan be represented, with correct whole-body/source identity and hand+prop relation, BEFORE segmentation or rigging? Are complex characters ever silently replaced by tube SVG actors?

M. Will an unapproved world/character or asset family be blocked from the full render, even after session restart?

N. Can one iteration investigate multiple connected high-impact gaps, preserve competing causes and route fixes to observation vs recipe vs provider vs mask vs animation? Is user visual review persisted?

O. Can the system report `ENGINE_IMPLEMENTED`, `VLM_COVERAGE`, `REAL_ART_QUALITY`, and `TRANSFER` separately without making image-quality claims based on code tests?

If any critical question fails, coding agent must repair the **upstream mechanism** and re-export a new ZIP. The audit is a preflight of actual implementation, not a test of professional artistry.
