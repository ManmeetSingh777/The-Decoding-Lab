    actual visual quality are separate independently reviewed gates.

    all advanced production outcomes stay open pending authentic evidence.

## C. Exact status words and promotion order

Use a single authoritative enum for each *individual capability*:

- `NOT_IMPLEMENTED` — no real executing path.
- `IMPLEMENTED_UNTESTED` — executing code exists; no adversarial evidence.
- `OFFLINE_VERIFIED` — production-path negative tests pass under simulated inputs.
- `REAL_SOURCE_UNCALIBRATED` — real images/audio accessible but native art truth unreviewed.
- `SOURCE_ART_REVIEWED` — exact source visual/audible claims reviewed, limitations explicit.
- `SKILL_CANDIDATE` — evidence-bound conditional method; not yet qualified transfer.
- `SKILL_TRANSFER_QUALIFIED` — independent original subject + contrasts + ablations passed.
- `ORIGINAL_AUDIOVISUAL_QUALIFIED` — actually rendered held-out multi-subject AV film reviewed.
- `BLOCKED:<exact reason>` — missing authority, source or operation, no silent workaround.

**Do not generate one status by averaging unrelated domains.** Report status
for `OBSERVATION`, `SOURCE_ART_TRUTH`, `SOURCE_CHARACTER_ART`, `TEMPORAL_SCENES`,
`AV_MEANING`, `CLUSTER_QUESTION`, `CONDITIONAL_SKILL`, `REFERENCE_AUTHORITY`,
`IMAGE_COMPILER`, `CHARACTER_ASSET`, `MULTIACTOR_MOTION`, `CAMERA_ATTENTION`,
`AUDIO_MUX`, `RENDER_GATE`, `COLD_REPLAY`, `HELDOUT_TRANSFER` independently.

## D. Test-quality rules and historical failure prevention

1. Add a **positive and negative** case for each row. A negative must fail
   with the precise root-cause code; a different exception is NOT a test pass.
2. Tests must invoke the real production functions and capture their outputs,
   not just a sample schema validator. Use `test_reference_guards.py` (29
   synthetic cases) and `test_archived_wiring.py` (5 real-module smoke tests)
   as *seed tests*; add deeper end-to-end scenarios using actual compiler/adapter.
3. Kill each essential guard with a mutation and show that the negative test
   becomes red. If mutation survives, the test is a superficial assertion.
4. Do not turn a false-negative into PASS by weakening requirements or changing
   expected status. If data is missing, expose `BLOCKED` and the exact missing
   input instead of pretending coverage.
5. Use no live API keys/paid calls/network/source uploads without recorded
   explicit approval. A fake can establish wiring but not artistic perception.
6. Run final slow tests only on final code and in fresh independent extraction.
   Record precise failures/skips, duration, exit status, dependency versions,
   commit SHA, ZIP content hashes and determinism; *no* previous-green reuse.

## E. Required integrated positive proof before real 15+1

Offline: a novel *two-actor scene* is driven by at least one source-bound art
method and one distinct motion/attention operation; image payload uses immutable
source-conditioned clauses, multiple source roles where required, distinct
canonical identities and approved drawing states; rendering rejects broken
technical signals; the causal counterfactual changes the correct local output.
All of it must survive a fresh directory/capsule restore.

Then, **with user consent**, perform one bounded real native-source artistic
calibration sequence, including character redraw, shading/light, simultaneous
action, camera/world and an AV cue, with human comparison against actual pixels
and one original construction/counterfactual. Only then may the result justify
starting the full 15+1 analysis. That real-world test is an independent
validation of the already-complete design, not permission to postpone its
foreseeable engineering gaps.
